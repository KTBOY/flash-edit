## 二、追加修复轮次（用户反馈驱动，每轮重建 + 实测）

| 轮次 | 反馈 | 根因 | 修复 |
|---|---|---|---|
| F4 | 提示框不自动消失 | 只清文字，白底边框残留 | 2000ms 后整条 `_visible=false` + `selectable=false` |
| F5 | 要能手动关 | 无关闭入口 | 加 ✕ 按钮（游戏自带 `工作名称` 符号） |
| F7 | 首页读档要自由选档 | 原逻辑读"最后槽位" | 挂游戏自带「系统设置」面板 `gotoAndStop(4)` 读档页 |
| F8 | 换衣服没保存 | 只存标量 `衣服`，漏数组 + 外观帧不恢复 | 新增数组表 + 显式恢复外观帧 |
| F9 | HUD 显示 undefined | `主面板.更新()` 执行早于存档恢复 | 存档应用后**再调** `_root.主面板.更新()` |
| F10 | 所有变化都要能存 | 显式变量表会漏剧情标志 | 保留 `for...in` 兜底遍历 |
| F11 | 名字栏在进入房间时被重置 | 同上（进入房间早期刷新） | 应用后补刷 |

## 三、三条硬规则（本轮沉淀）

1. **Ruffle 中运行时自绘 MC 按钮不响应点击** → 复用游戏自带按钮符号/面板。
2. **数组类状态单独存**（`typeof == "object"` 绕过标量过滤）；**外观类状态**（`_currentframe`）显式恢复。
3. **存档应用后必须调游戏自己的 UI 刷新函数**，否则 HUD 显示 undefined / 旧值。

## 四、非补丁缺陷（原版固有，勿当 bug 修）

- 游戏内"输入名字"依赖老式 FocusManager，Ruffle 下报 `Unable to attach 'FocusManager'` 且无法打字 —— 原版固有，正常 Flash Player 环境不受影响。
- 4399 的 `ctrl_mo_v2.swf` 从 CDN 加载，离线运行静默失败，对补丁无影响。
- 开场对话原版在 Ruffle 中推进不可靠 → 补丁直接跳过（不影响游戏内容/结局）。

## 五、测试提示

- 三层嵌套包装（12MB 级）需 **40~45s** 才到首页；简单 SWF 20~25s。
- 点击用**轨迹式**（move→停顿→down→up）；会话首次点击会被吞，先对空白区预热。
- 页面坐标 = 舞台坐标 + 画布偏移 `(30, 0)`。
