# 使用教程（Cheat Engine 工作流）

## 准备

```bash
npm install     # 会自动复制 Ruffle 运行时（postinstall）
npm run dev     # 启动开发版
npm run build && npm run dist   # 生产构建 / 打包 Windows 安装包
```

## 加载游戏

三种方式任选：

1. **打开 SWF**：系统文件选择框（支持 `.swf` / `.spl`）；
2. **拖拽**：把 `.swf` 拖进左侧播放器区域；
3. **网络加载**：输入 http(s) 的 SWF 地址（需目标站允许跨域）。

加载后左下状态栏会出现"WASM 内存块"，出现即代表修改器已就绪。

## 修改血量/金钱（标准四步）

以"金币 100 → 想改成 99999"为例：

1. **首次扫描**：扫描面板输入 `100`，方式选「精确值」，点「首次扫描」。
   会得到一批候选地址（通常是几千个）。
2. **改变数值**：回游戏里花掉/获得一些金币，让金币变成一个新值，比如 87。
3. **再次扫描**：输入 `87` 再点「再次扫描」→ 候选骤减；重复 2~3 轮通常收敛到个位数。
   - 不知道精确值时：方式选「增大了 / 减小了 / 变动了」；
   - 完全不知道初始值：首扫直接选「未知初始值」建立基线，之后用「增大/减小/变动」收敛。
4. **修改/锁定**：
   - 「写入」：填新值点写入，立即生效；
   - 「锁定」（挂锁图标）：加入修改列表并持续写回——无敌、不减金币用这个；
   - 「全部写入」：把剩余所有候选一次写成同一个值（收敛到少量候选后的暴力手段）。

误删误扫可点「撤销本次」回退一步（最多 5 步）。

## 修改伤害

- **改攻击力属性**（推荐）：属性是持久变量，流程与金钱完全相同；
- **抓单次伤害结算值**：伤害是瞬态值。先记住打出的数字，选「未知初始值」首扫，
  再打一次，用「精确值 / 介于」在结算瞬间连扫收敛。扫不到时退回改属性。

## 打包 EXE（Flash 转 EXE）

把任意 SWF 变成双击即玩的单文件 EXE：**头部「打包 EXE」按钮**。

- **来源**：当前加载的游戏，或点「选择 SWF」选任意本地文件；
- **播放器**：默认内置 Flash Player 32 独立版（随应用分发，位于 `resources/flash-projector.exe`）；
  也可选择你自己的 projector EXE；
- **原理**：Flash 独立播放器原生支持读取附加在自身末尾的 SWF，文件结构为
  `[播放器] + [SWF] + [魔数 0xFA123456] + [SWF 长度]`，拼接后即得自运行 EXE；
- 生成的 EXE 约 10MB（播放器体积）+ SWF 大小，直接双击运行，无需任何安装。

想分发**修改版游戏**：先「写入 SWF」生成补丁文件，再用「打包 EXE」选择该文件打包。

## 写入 SWF（把修改固化为永久修改）

运行时修改在重启游戏后失效；想得到一个"天生就是修改版"的 Flash 文件，用
**修改列表 →「写入 SWF」**：

1. 像往常一样扫描并修改数值后，进入修改列表，点「写入 SWF」；
2. 弹窗中每条修改显示 **原值 → 新值**。原值是进入列表时的数值，可手动修正
   （写入 SWF 靠"在文件里找到等于原值的常量"来定位，所以原值必须准确）；
3. 点「分析命中」——显示每个修改在文件里命中的常量个数：
   - 命中 ≥1：可以固化；
   - 命中 0：文件里没有这个值的常量（数值是运行时算出来的，或以小整数指令内联），
     这类修改无法固化，属正常现象；
4. 点「另存为…」生成 `xxx_modified.swf`（不覆盖原文件），用本工具或浏览器打开验证。

原理与边界：AS3 游戏改写 ABC 常量池（double 池 + 整数池），AS2 老游戏按双精度
字节匹配；运行时计算得出的数值（如 攻击力×等级）不会被固化。网络加载的游戏
没有本地文件，不支持此功能。

## 变速

设置页 → 变速齿轮，滑杆 0.1x–10x（0.1–5 为常用区）。对帧循环与计时器驱动的游戏生效。

## 修改配置（存档）

- 每个游戏的修改列表和速度会按**游戏内容指纹自动保存**（`userData/data/profiles.json`），
  下次打开同一游戏自动恢复；
- 重启游戏后内存布局可能变化，恢复时会自动校验：地址读不到的条目标记「地址失效」并自动解锁，
  重新扫描后重新锁定即可；
- 扫描出的地址只在**本次会话内**稳定，这是与 Cheat Engine 一致的已知限制。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 扫描很慢 | 首扫需遍历全部 WASM 内存（数百 MB），正常几秒内；后续再扫只过滤候选，很快 |
| 候选数降不下来 | 换更独特的数值（如金钱 1234 而不是 0/100），或用「变动/未变动」代替精确值 |
| 改了没效果 | 该游戏可能校验数值（加密/双存储），尝试锁定 + 连续改，或放弃该值 |
| 小数扫不到 | 设置页把浮点容差放宽到 1e-3（单精度小数场景） |
| 游戏跑不起来 | Ruffle 兼容性问题，可到 Ruffle 上游反馈；本项目依赖其模拟完备性 |
