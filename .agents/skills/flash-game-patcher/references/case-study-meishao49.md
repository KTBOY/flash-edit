# 实战案例：《美少女成长计划 4.9 无限金钱版》存档补丁

完整记录（2026-10-16），作为同类游戏（4399 包装的 AS2 养成游戏，如《皇后成长计划》系列）的参照。

## 一、目标

- 原 SWF：`美少女成长计划4.9版本_无限金钱版.swf`（12.79MB）
- 问题：首页【读取记忆】按钮点了没反应（游戏本身没有存档功能）
- 需求：增加存档功能（用户指定参考《皇后成长计划》，其用 SharedObject 单槽位存档）
- 成品：`美少女成长计划4.9版本_无限金钱版(带存档).swf`（原版保留）

## 二、游戏结构（三层包装）

```
美少女成长计划4.9版本_无限金钱版.swf (System4399Manager 壳)
 └─ L4399Main_gamefile.bin (chid 3, 12.757MB) = inner_game.swf
     └─ DressUp_4399_Main_gamefile.bin (chid 3, 12.635MB) = game_l3.swf ← 游戏本体(AS2)
```
- 外层/二层是 AS3 的 4399 包装（加载 ctrl_mo_v2.swf 失败则离线运行，游戏照常）
- 游戏本体：SWF v10、640x480、26fps、**主时间轴 11 帧**
- 反编译脚本 454 个；中文变量名 = 全局状态（挂 `_root`）

## 六、回编管线（实际执行）

```bash
# A. XML 编辑（按钮注入）→ 回编
java -jar ffdec-cli.jar -swf2xml game_l3.swf l3_full.xml
python inject_action.py l3_full.xml 159 <hex> l3_patched.xml
python inject_action.py l3_patched.xml 1039 <hex2> l3_patched2.xml
java -jar ffdec-cli.jar -xml2swf l3_patched2.xml stage1.swf

# B. 脚本补丁
java -jar ffdec-cli.jar -importScript stage1.swf stageF.swf scripts_final/

# C. 逐层回嵌（先用 ASCII 短名绕过中文长名 I/O error，最后再改回中文名交付）
cp inner_game.swf inner_ascii.swf
java -jar ffdec-cli.jar -replace inner_ascii.swf inner_patched.swf 3 stageF.swf
cp "原版外层.swf" orig_outer.swf
java -jar ffdec-cli.jar -replace orig_outer.swf out_final.swf 3 inner_patched.swf
mv out_final.swf "美少女成长计划4.9版本_无限金钱版(带存档).swf"
```

## 七、验证结果（Ruffle 实测）

1. ✅ 首页【读取记忆】无存档 → 显示"没有找到存档 no save found"提示
2. ✅ 系统→存档→槽位1 → **"存档成功 save ok slot1: 名字 13y 1764/1/1"** + 槽位标题刷新 + localStorage 出现存档数据
3. ✅ 读档页正确显示槽位1的存档标题、槽位2/3 显示 empty
4. ✅ 点击槽位1读取 → 回到主房间，HUD（日期 1764/1/1、金钱 0999999）与存档一致
5. ✅ **关浏览器 → 重开 → 首页【读取记忆】→ 成功进入游戏**（跨会话）
6. ✅ 消息文本用内嵌字体 FZCuQian-M17S 渲染（缺字部分由小写 ASCII 兜底）

## 八、遗留说明（非补丁缺陷）

- 游戏内"输入名字"依赖老式 FocusManager，在 Ruffle 下会报 `Unable to attach 'FocusManager'` 且无法打字——**原版游戏固有**，正常 Flash 环境不受影响
- 4399 的 ctrl_mo_v2.swf 从 CDN 加载，离线运行时静默失败，对补丁无影响
- 开场对话原版在 Ruffle 中推进不可靠，故跳过（不影响任何游戏内容/结局）

## 九、本案例的复用检查表（下次改同类游戏）

1. `-export binaryData` 剥层 → 找到 AS2 本体
2. `-export text` 搜"读取/存档"→ 在 XML 找按钮 chid → 检查是否空动作
3. 找状态初始化函数（搜索 `function 初始`/`function 重置`） → 收集变量表 + 数组表
4. harvest 采集两个动作字节码 → inject 注入
5. 找【系统】面板的帧结构与槽位按钮（找对称排列的相同 chid）
6. importScript 打脚本补丁（存档系统模板改游戏函数名）
7. 回嵌（中文名 I/O 报错就先换 ASCII 名）→ Ruffle 测试（先校准【系统】【槽位】坐标）

## 十、追加修复轮次（实测驱动，全部验证通过）

首版存档可用后，用户实测反馈逐条修复（每轮都重建 SWF 并用 Ruffle 验收）：

| 轮次 | 用户反馈 | 根因 | 修复 |
|---|---|---|---|
| F4 | 提示框不自动消失 | 只清文字，白底边框残留 | 2000ms 后整条 `_visible=false` + `selectable=false` |
| F5 | 要能手动关掉 | 无关闭入口 | 加 ✕ 按钮（用游戏自带 `工作名称` 按钮符号，**非自绘 MC**） |
| F7 | 首页读档要自由选档 | 原逻辑是"读最后槽位" | 改挂游戏自带"系统设置"面板 `gotoAndStop(4)` 读档页（作者时按钮可靠） |
| F8 | 换衣服没保存 | 只存标量 `衣服`，漏了数组 `所有衣服`/`商店的衣服`，且外观帧不恢复 | 新增**数组表**机制 + 应用时恢复 `人物.gotoAndStop(年龄阶段)` / `人.gotoAndStop(衣服)` / 背景季帧 |
| F9 | HUD 显示 undefined | `主面板.更新()`（读名字）执行早于存档恢复 | 存档应用后**再调** `_root.主面板.更新()` |
| F10 | 要求所有变化都能存 | 显式变量表会漏剧情标志 | 保留 `for...in` 兜底遍历（覆盖事件标志/剧情进度） |
| F11 | HUD 名字在进入房间时被重置 | 同上，进入房间早期刷新 | 同上，应用后补刷 |

### 本轮沉淀出的三条硬规则

1. **Ruffle 中运行时自绘 MC 按钮不响应点击** → 一律复用游戏自带按钮符号或面板（见 testing 文档「三点五」）。
2. **数组类状态必须单独存**（`typeof == "object"` 绕过标量过滤），外观类状态（`_currentframe`）**必须显式恢复**。
3. **存档应用后必须调用游戏自己的 UI 刷新函数**，否则 HUD 显示 undefined / 旧值。
